# Profile v1 (T25): the private hub, lists, one-time sheet and public pages

Branch `ui/v3-profile`, from `origin/v3` after the T24 backend (#89). Built against the T24 contract and wired to it directly.

## What changed
- **Hub `/profile`:** initials circle, name, `@username · reading since`, bio, "Edit profile" (inline name, username, bio with a 160 counter; only changed fields are sent), the visibility row (Make public asks for a username first; the link `bookvane.me/u/{username}` shows once public), "Your {year} in books" (sentence, 12 bars, up to 3 genre chips), "Your lists" with "New list", and a quiet "Account settings" link to `/account`.
- **List `/profile/lists/:id`:** numbered books with each book's shelf status (owner view only), the visibility row, Edit (rename, description, Move up, Move down, Remove, Delete list with a confirm). Each move sends the full `PUT …/order`; a failure puts the list back.
- **Add to list:** a quiet button under Want / Own on the full book page, for signed-in readers. Checkboxes per list plus "New list…". It does not appear on book cards or for private entries.
- **One-time sheet:** driven by `show_prompt`, a bottom sheet on phones, a centred dialog on desktop. Both buttons and Esc send `prompted: true`. It waits for the next page if the reader is on the import page, a sign-in screen or the guest save dialog.
- **Public pages `/u/:handle` and `/u/:handle/lists/:id`:** read only, built from the public payload; 404 shows the existing not-found page; guests get one line with Create free account to `/register?src=profile`; a reader viewing their own page sees "This is how others see your profile."
- **Entry point:** the header account link and the You tab now go to `/profile`. `/account` is unchanged.
- `profile` added to the sign-up source allow-list in `events.js`.

## Choices the brief left open (please confirm)
- Public year sentence is third person: "Finished 18 books and 5,940 pages this year. July was their biggest month." The brief only gave the first-person text.
- Public pages show no genre chips (the brief lists only the sentence and bars).
- The status line on a list uses what the API returns: "Finished · {month}" when there is a finished month, else "Owned" or "Want to read". The API has no "Reading" status.
- "Add to list" needs to know which lists hold the book. I build against `GET /me/lists?book_id=ID` returning `has_book` on each row; a missing flag means "not on it".

## Tests
`tests/profile.spec.js` (mocked API): sheet shows once and both paths send `prompted`; Esc; private by default; the You tab; public round trip with `handle_required` and `handle_taken`; edit sends only changed fields; the year sentence for plural, one book, no biggest month and an empty year; list create, share, rename, delete and the 50-list limit; keyboard reorder with the full order sent and rollback on failure; Add to list; guest and not-found pages; the public pages carry none of the never-public fields; `src=profile` reaches the sign-up request. Screenshots (`PROFILE_SHOTS=1`) go to `frontend/node_modules/.bv-preview/profile/` and are not committed.

## Behaviour worth knowing
- If the profile is slow, fails or comes back malformed, `/profile` still shows an "Account settings" link, so Sign out stays reachable.
- 422 `handle_reserved` shows "That username isn’t available."
- Public pages are cached for 60 s by the server; there is no cache-busting.
