## Implemented scope and layers

- **Data/schema:** reuses existing work-level Books, private UserBooks, reading attempts, explicit preferences and catalogue associations. No migration/table/index or persistent skip/profile/event data. Existing IDs, flags, notes, history and auth remain unchanged.
- **Service:** `services/next_read.py` applies source/owner/activity/metadata eligibility and preference scoring in SQL over the whole eligible set, then fetches at most60 lightweight candidates and authors in one batch. Preference counts use indexed tag lookups within that SQL statement, not individual application requests. Select up to three with diversity by stable author ID when alternatives exist in that pool. Same-name authors are not merged. Private author text is only a diversity hint, never an identity. No notes, descriptions or full histories are loaded for choices.
- **Eligibility:** default Want only; active/paused excluded. Finished/stopped books can return only after the reader explicitly requeues them. Explicit catalogue mode excludes queued works and unrequested historical revisits, but can include unread books already marked Own. No automatic catalogue padding. Private Want entries remain eligible without catalogue metadata.
- **Controls/ranking:** optional owned-only, a genuine covered broad interest and a user-selected maximum known catalogue page count. No page/time/mood guesses. Broad genre/topic/form/audience options are scoped to eligible works; sparse mood/theme controls are not advertised. Exact existing preference matches can influence rank, capped at three; ownership is modest convenience, not default eligibility. Current interest and length filters apply in SQL. Existing V2 tag visibility/public APIs are not changed.
- **Rotation:** deterministic source/work hash plus page-local UUID/round, not global random ordering or a learned preference. Up to30 recent choice keys are excluded per request; large queues can revisit older choices after that bounded window. Filters persist when switching source or rotating. No skip writes or durable dislike/profile. Explicit start over clears controls/exclusions.
- **API:** authenticated `GET /me/next-read`, bounded validated query model, narrow response/reason codes, private no-store and existing access-log redaction/rate limits. Capabilities advertise `next_read`/M4 only on this backend. Richer read-only libraries can view choices but existing write guards still prevent starts.
- **Frontend:** `NextReadSection.jsx` is shared by Home and a newly confirmed finish. Finish success stays separate from failed/malformed suggestion requests; skip is quiet and returns focus. Historical records/reloads do not manufacture a new finish celebration. No mandatory note, rating or progress. Cards distinguish Open from explicit Start. Starting re-reads current owner/version, retains retry identity, opens an already-active reading instead of duplicating it, refuses a stale new reread, and uses existing ensure/attempt commands with `started_via=next_read`. One parent command gates conflicting starts/controls and survives suggestion refetches. Account/route guards keep private choices out of a departed session.

## Decisions and boundaries

These implement the approved deterministic, shelf-first architecture, not a new recommendation platform. Catalogue exploration is explicit and reversible; it does not secretly replace the queue. Metadata filters explain excluded unknown lengths/private fields. A finish prompt is a successful current-session transition, not inferred from an imported/history row’s creation/update time. M4 does not add a persistent “recent finish” activity record or interpret reactions/notes as a taste profile.

The UI lead reviewed the intended interaction read-only: keep finish success independent, Want-first source labels, reversible source switches retaining controls, explicit Open versus Start, honest metadata reasons, bounded rotation and one quiet skip. React/database/full-flow verification guidance informs existing-component reuse, account guards and isolated tests, without replacing the app architecture.
